## 实际链路

请求最终结果由 middleware 的 DetailedOutcomeRecorder 写入 opsagg 分钟桶；请求、管理操作和系统事件共享 audit Redis Stream。cmd/server/main.go 负责实际接线。API 的 /api/ops/overview 查询桶、合并渠道、读取延迟样本和账号池；ops.js 展示并向日志中心传递窗口/渠道。cmd/server/alerts.go 每分钟用最近 30 分钟数据评估 alerting.Engine，状态转换写入系统日志。

保留现有 Go 模板和原生 JavaScript，不引入 Vue。

## 本次修复

- 全部渠道汇总补齐缓存/推理/总 Token、计价和未计价请求及 Token、费用。总 Token 继续以供应商上报为准，旧桶缺失时使用输入与输出之和。
- 审计队列同时限制条数、单条大小和序列化字节：256 条、32 KiB/条、8 MiB 总预算；入队时快照序列化内容，避免调用方后续修改 Metadata 改变待写日志。Close 可重复调用且不再与 Log 竞争关闭通道。
- 审计健康信息提供 queue、queued_bytes、written、dropped、write_failed、last_success、last_failure、closed；指标聚合独立提供 written/write_failed。均为本进程启动后的计数，不是集群总数或当前故障率，重启后重置。
- 页面显示采集丢失警示和健康计数。Redis 读取失败与真实零条记录分开表示；查询失败后健康提示标为未更新。
- 渠道发现、延迟样本、模型样本和渠道矩阵读取失败传回 API，不能伪装成空流量或无延迟样本。
- 延迟列表按最多 32 个桶一批进行 Redis pipeline 读取，减少逐桶串行网络往返；每个列表查询最多 5000 个样本。
- 指标写入使用 2 秒 context 预算，总览查询 8 秒预算，告警评估 15 秒预算，并继承调用/服务取消信号。网络客户端实际超时行为仍受 Redis 连接配置约束。
- 告警读取账号池、桶或延迟证据失败时跳过整次评估，保留已有告警状态，不产生错误的恢复事件。

## 统计边界

请求统计继续区分最终结果与上游尝试；探测/http 基础设施聚合不进入全部渠道业务汇总。TTFT 缺失不补零。P95 是保留样本的最近秩分位数：渠道分钟桶最多最近 5000 个、模型桶最多最近 2000 个，并非高流量下所有请求的精确 P95。查询按整分钟桶边界覆盖，边界分钟可包含所选秒级窗口之外的记录。

聚合默认保留 8 天，但趋势查询最多 24 小时；审计 Stream 按条数约裁剪。覆盖时间仍由实际最早/最新记录决定，不将配置天数视为完整历史。本次未对生产 Redis 数据覆盖范围进行测量，未调整保留策略或清理数据。
