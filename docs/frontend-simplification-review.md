本记录为前端精简完成时的快照；后续版本升级功能的当前上线信息见 [online-upgrade.md](online-upgrade.md)。

ConsoleAPI 明确检查 HTTP、JSON 类型及列表/信封合同，传递取消信号，同源携带会话，不自动重试写操作。401 跳转登录，403 保留页面并报告权限错误。列表失败保留已有数据。设备授权继续保留各渠道端点、Grok 官方域名限制、设备码、弹窗预留/手动链接、刷新恢复、取消与过期处理，并阻止轮询重叠及过期响应覆盖新事务。

## 结论

可以进行较深入的精简。收益主要来自删除旧兼容分支、合并重复行为和明确样式归属。现有 Go 模板、原生 JavaScript、CSS 足以完成这些工作；引入新框架不是必要条件。

将大文件拆成多个小文件可以改善维护，但不代表代码总量减少。应以生产代码净减少、重复实现减少和行为保持为验收依据。

## 第一批：低风险、真正减少代码

### 1. 删除旧缓存与内存估算样式

入口：web/static/css/config.css:205、web/static/css/main.css:937、web/static/css/main.css:1051。

config.css 保留完整的 Cache details & memory estimates 区域，包括 config-cache-details、estimate-note、estimate-note-warn、estimate-caption-ok/warn。main.css 保留 estimate-panel、estimate-grid、estimate-card 及颜色、标题、数值样式。

当前配置页模板和配置脚本已无这些展示入口，config_ui.test.cjs 也检查页面不再含模拟缓存区域。可成组清理，并从混合选择器和响应式规则中移除对应成员；不能整段删除仍服务其他组件的分组规则。

### 2. 删除读取真实 token 的旧前端回退

入口：web/static/js/accounts.js:1737、web/static/js/accounts.js:1773；接口依据：internal/api/api.go:640。

accountOutput.MarshalJSON 始终写入 has_credential，并删除 token、oauth_access_token、workbuddy_access_token 等凭据字段。账号列表和写入后的返回使用该投影，account_leak_guard_test.go 有对应约束。

formatTokenDisplay 仍保留读取和截断旧 token 的逻辑；workBuddyIdentityLabel 仍保留 access token 尾部作为身份回退。对于当前前后端配套部署，这些分支无法从正常账号接口获得数据，可以删除。保留 has_credential、email、UID 等当前合同字段；缺失信息显示未知或占位，不将缺失状态默认视为正常。

### 3. 合并分页实现

入口：web/static/js/accounts.js:1452、web/static/js/models.js:283。

两处均实现首页、上一页、最多五个邻近页、下一页、末页及点击处理。可以共用分页函数，让页面仅传容器、页码、总页数和回调。按钮外观交给统一样式，避免继续保留两种行内 padding。

### 4. 复用已存在的侧栏统计更新

入口：web/static/js/common.js:3、142；web/static/js/accounts.js:1542。

账号页已使用公共异常判断，但仍独立计算计数并逐个查找、写入侧栏节点。可以直接复用 computeSidebarAccountStats 和 setSidebarAccountStats，再更新账号页专有统计。应保留账号页避免额外请求的现有逻辑。

## 第二批：中等风险，合并重复行为

### 5. Grok 授权接入公共设备授权驱动

入口：web/static/js/accounts.js:416、web/static/js/device-auth.js:20。

WorkBuddy、Qoder、Cline 已使用 DeviceAuthLogin.create；Grok 仍在账号脚本中维护独立 state、start、poll、stop、reset 和窗口打开逻辑，约一百行。

应让公共驱动提供必要适配点，并删除 Grok 的重复生命周期实现。适配点包括授权链接校验、verification_uri 回退、设备码展示和完成回调；保留 Grok 专属端点及 auth.x.ai URL 限制。不能直接把其他渠道的参数复制过去：Grok 目前的响应和展示要求存在差异。

三份现有渠道包装文件仅约 38–39 行，各自承载端点与错误文案，优先保留；将它们合成一个配置文件未必带来足够净收益。

### 6. 统一请求基础层

入口：accounts.js:23、models.js:622、config.js:283、366，以及日志和运维请求。

各页重复处理会话过期、HTTP 错误、JSON 和错误提示。配置加载已有较完整的 HTTP/Content-Type 检查；账号、模型和 Key 列表的检查较弱。账号列表在接口返回错误对象时会把它转为 []，可能将请求失败展示为空列表。

建议共用小型 requestJSON/requestText 工具，统一状态检查、错误信息提取、同源会话和 signal 转发。裸数组、对象以及配置接口的 code/data 信封由明确适配处理，不按猜测自动拆包。不默认重试创建、保存、删除或授权事务。

### 7. 统一 DOM 基础函数和模态框外壳

入口：config.js:5、ops.js:145、logs.js:217、alerts.js:51、models.js:16。

多个页面重复定义 el、make、attach、setText；模态框也重复开关外壳。可复用轻量公共工具。确认文本转换、空值处理和节点追加行为后再合并，避免因看似同名而改变表现。

common.js 已包含账号额度与状态业务，不宜把所有代码继续堆进去。可将界面工具和账号业务分别收敛到明确命名空间，避免多个全局 openModal、setText、renderPagination 依赖页面恰好没有一起加载。

## 第三批：收益较大，但需逐页行为与视觉验收

### 8. 统一桌面与移动列表的数据描述

入口：accounts.js:849、1363；models.js:363、567；config.js:411、511。

三个页面均在渲染时按 640px 断点选择两套 DOM。模型页已复用部分字段片段，账号页也已有 quota/status 等公共字段函数，不能将所有双端代码都计算为重复。

进一步精简可让行数据和列描述只生成一次，由 CSS 将桌面表格转为移动卡片；当前 ops.css 已有 data-label 驱动的先例。先从 Key 列表开始，再做模型和账号。账号页字段较多、Cline 列可见性不同，迁移风险最高。

必须保持选择状态、批量操作、稳定 ID、长文本、列隐藏和触摸操作。现有三页未见基于断点变化的重新渲染监听，单 DOM 方案还可减少窗口跨断点后保持旧呈现的问题。

### 9. 收敛 CSS 归属与模板外壳

main.css 中存在 accounts/models/ops/logs 等页专属选择器，页面 CSS 又定义同名选择器。跨文件出现不等于无效覆盖，有些是基类和媒体查询，应逐个核对最终层叠关系。

main.css 保留布局、主题、按钮、表单、基础表格、反馈；页面 CSS 保留业务布局和差异。清理时在原规则处修改，避免再追加一层覆盖。登录页的 ambient-bg/blob/grid-orbit 标记及对应 no-op CSS 可以一起移除。

Go 页面已复用 doc-head、sidebar 和 modals，框架并未完全重复。可继续共用 main.css/common.js 的引入片段和页面标题外壳，但各页独有 CSS、脚本顺序和模态框注入要保持明确，不用复杂模板系统换取少量标签减少。

## 必须保留的行为

- WorkBuddy/Qoder/Grok/Cline 的额度与授权合同差异；未知、估算、实测和确认不能合并成一个数字。
- 官方登录的取消、恢复、弹窗拦截回退、过期清理和 URL 限制。
- Key 只在创建/重置时显示完整值，列表不得改回复制掩码。
- 运维统计口径、筛选竞态保护、后台页暂停刷新、下钻条件和返回上下文。
- HTML 转义、稳定业务 ID、功能入口控制、主题和移动端可访问性。
- provider-registry.js 由后端定义生成，不恢复多份硬编码通道名单。

## 推荐实施顺序与验收

1. 删除无入口样式与旧 token 回退，合并分页和侧栏计数。
2. 接入公共授权驱动，统一请求、DOM 和模态外壳。
3. 逐页合并双端列表，整理 CSS 归属和模板片段。

运行现有前端测试、相关 Go 接口/模板测试。测试中既有真实执行断言，也有检查源码字符串或注入私有变量的断言；重构时保留行为断言，避免仅为通过旧字符串断言保留重复实现。运行 Go 测试时用 amd64，以免当前本机默认 386 的 miniredis 整数范围造成误报。

浏览器验收覆盖宽屏、手机、明暗主题、空数据、请求失败、会话过期、跨断点变化、选择与分页、四渠道授权、快速筛选、图表下钻和返回。授权流程避免因检查而创建真实账号或启动未授权上游操作。

目前未做浏览器 CSS 覆盖率采样，未承诺精简百分比。现有前端总体原始体积约 516 KiB，也没有庞大的框架依赖；本轮最大的价值是减少多份行为实现及维护分叉，而非单纯压缩传输体积。
