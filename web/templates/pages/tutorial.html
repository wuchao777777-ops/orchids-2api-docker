使用教程

按顺序完成账号、API Key 和客户端地址配置。

快速接入 渠道地址 导入 CC Switch 常见问题

快速接入

先让渠道可用，再把面板 API Key 交给客户端。

  1. 1

    添加渠道账号

    前往「账号管理」，从页面发起对应渠道的官方授权登录，不需要手动填写上游凭据。

  2. 2

    创建 API Key

    前往「配置管理」创建 sk-...，这是客户端使用的凭据。

  3. 3

    配置客户端

    从下方表格复制渠道地址，填入 API Key 和该渠道支持的模型。

不要混用两类凭据 渠道账号凭据只用于账号管理；客户端统一使用面板创建的 sk-...。

客户端配置示例

以 OpenAI 兼容客户端接入 WorkBuddy 为例；模型 ID 请从模型管理或该渠道 /v1/models 获取

{
  "base_url": "/workbuddy/v1",
  "api_key": "sk-...",
  "model": "替换为当前目录中的模型 ID"
}

渠道地址

四个渠道均支持 OpenAI Chat Completions、Responses（Codex）和 Anthropic Messages（Claude Code）。表中是 Base URL，客户端会继续追加 /responses、/messages 或 /chat/completions。

OpenAI / Codex /{渠道}/v1

OpenAI 客户端追加 /chat/completions；Codex 使用 Responses 协议并追加 /responses。

Claude Code /{渠道}

Claude Code / Anthropic SDK 自动追加 /v1/messages。地址末尾不要添加 /v1。

渠道与账号方式 OpenAI / Codex Claude Code 模型选择 协议
WorkBuddy 使用官方网页登录 以当前渠道目录为准 Claude OpenAI
Qoder 使用官方设备授权 以当前渠道目录为准 Claude OpenAI
Cline 使用 WorkOS 设备授权 以当前渠道目录为准 Claude OpenAI
Grok 使用 Grok Build OAuth 设备授权 以当前渠道目录为准 Claude OpenAI

一键导入 CC Switch

选择客户端和渠道，填写面板 API Key，读取目录后选择模型。

尚未读取目录

先安装 CC Switch，允许浏览器打开应用，在应用中确认导入后手动启用提供者。API Key 仅用于同源目录请求和本机导入，不保存在浏览器存储；导入链接含密钥，请勿分享。网页无法确认应用是否完成导入。

协议接入不代表每个模型都支持视觉、托管搜索或全部工具。模型能力和账号权益以实际目录与上游为准；统一入口可使用站点 /v1（OpenAI）或站点根地址（Claude Code），按模型路由。

常见问题

先按现象定位，不必逐段翻阅渠道说明。

Claude Code 请求 404，地址像是多了一层

Claude Code 的地址应为 /{渠道}，删除末尾的 /v1。OpenAI / Codex 仍需保留 /v1。

客户端提示未授权或 API Key 无效

客户端应使用「配置管理」创建的 sk-...，通常放在 Authorization: Bearer sk-...；Anthropic Messages 客户端也可使用 x-api-key。

渠道账号无法手动填写凭据

这是预期行为。WorkBuddy 使用官方网页登录，Qoder 使用 qoder.com 的 OAuth 设备授权，Cline 通过 WorkOS 设备授权（api.cline.bot）登录；Grok 使用 Build OAuth 设备授权。四个渠道都应从账号管理页面发起登录。
